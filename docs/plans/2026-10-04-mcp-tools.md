# MCP servers as tool sources for a session

Issue #16

## Scope
In: explicit JSON server configuration through CLI and library, stdio and Streamable HTTP, schemas, allowlists, approval, events, bounded failures and cleanup.
Out: MCP hosting/discovery, caller orchestration, implicit Qare environment-variable protocols, image content (owned by #48).

## Assumptions
- Use the official MCP SDK, with a bounded supported major version.
- `--mcp-config PATH` reads an object keyed by server alias. Each value specifies exactly one of `command` (plus `args`, optional explicitly supplied `env`) or `url` (optional headers). A positive timeout defaults to 30 seconds.
- Model names are `alias__tool`, portable across both providers. `--tools` explicitly names these tools; omitted permits all configured tools. No external tool is exempt from approval.
- Server configuration and secrets are not persisted. Resume supplies the configuration again; recorded policy contains only tool names and root.
- An MCP startup/discovery failure produces status=error, stop_reason=mcp, exit 1, before any model call. A call failure is an ordinary tool error.
- Exhausted budget refusal occurs before server startup. All opened connections close on completion/error/cancellation.
