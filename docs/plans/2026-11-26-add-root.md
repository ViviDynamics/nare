# File tools in more than one directory: --add-root

Issue #319

## Scope
In: a repeatable `--add-root PATH` flag and `Policy(extra_roots=...)` in the library.
`read`, `write`, `edit`, `list` and `search` may resolve into an added root under the
same symlink and `..` rules as `--root`. Under `--bash-sandbox` each added root is
writable like the root, and the credential-location check covers it. `nare contract`
advertises the flag through the parser, and docs/contract.md documents it.

Out: read-only extra roots (the issue leaves them to a later mode). Read requirements
(`--require-read`, `--require-cited-reads`, `--cited-read-map`) still name paths under
`--root`; nothing asks for them in an added root yet, and the docs say so.

## Assumptions
- `--root` keeps its meaning: bash's working directory and the base for relative
  paths. An added root never changes where a relative path resolves.
- `--add-root` without `--root` is refused at startup (exit 2), naming both flags.
  The library refuses `extra_roots` without `root` the same way.
- An added root that is not a directory is refused at startup, like `--root`.
- Under `--bash-sandbox` an added root of `/` is refused, as a root of `/` is.
- The session's recorded policy gains `extra_roots` only when one is given, and the
  sandbox record's existing `writable` list carries them. The profile name stays
  `confined-1`: its rules are unchanged, only the list of writable folders grows.
- Additive under "What changes the version": a new flag and a new policy field with
  a default. The contract version stays 3.

## Tasks

  under the root, and `extra_roots` without `root` is refused.
- [ ] 2. Sandbox confinement writes into added roots: the Seatbelt profile and the

  inside an added root and an added root of `/` are refused, and a live confined
  write into `B` succeeds while one into `C` fails.
- [ ] 3. CLI flag: `nare run --root A --add-root B` builds the policy, `--add-root`
  without `--root` exits 2 naming both, a missing directory exits 2, and
  `nare contract` lists `--add-root` with a documented row in docs/contract.md.
